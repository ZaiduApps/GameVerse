# 游戏详情页评分与评论体系需求梳理

## 1. 目标

在游戏详情页落地独立的游戏应用评分与评论体系，替换当前“关联社区帖子充当评论区”的方案。  
评分要体现应用商店风格的抗刷分能力，评论支持楼中楼回复，后台支持邮箱提醒总开关与用户个人提醒开关。

## 2. 范围

- 页面：`/app/[id]` 游戏详情页（PC + 移动端）
- 用户中心：`/profile` 通知设置
- 数据层：`src/lib` 新增游戏评分/评论 API 适配层与评分算法模块
- 结构化数据：游戏详情 JSON-LD 聚合评分字段

## 3. 三端职责

### C 端（用户侧）

- 展示综合评分、评分人数、评分分布（1~5 星）
- 支持登录用户提交评分（1~5 星）
- 支持评论发布、评论回复（楼中楼）、评论点赞、回复分页加载
- 支持“评论被回复时邮件提醒”个人开关

### 管理端（后台侧）

- 提供“游戏评论邮件提醒总开关”
- 提供读取与保存接口，供前台管理入口调用
- 当总开关关闭时，用户侧开关展示为关闭并不可提交邮件通知

### 服务端接口侧（契约）

- 游戏评分摘要查询
- 用户评分提交
- 游戏评论线程查询
- 评论提交（支持 `parent_id`）
- 评论点赞切换与点赞状态批量查询
- 用户提醒偏好读取与更新
- 管理端提醒总开关读取与更新

## 4. 评分算法设计（应用商店风格）

目标：低样本时抑制极端高分，样本增大后更贴近真实用户评分。  
输出区间：`1.0 ~ 5.0`。

### 核心公式

1. 贝叶斯平滑分：

`bayesian = (v / (v + m)) * R + (m / (v + m)) * C`

- `R`：用户评分均值
- `v`：用户评分人数
- `C`：全站先验均值（默认 `4.2`）
- `m`：先验权重（默认 `16`）

2. 置信度分（Wilson 下界映射到 5 分制）：

- 将 4 星/5 星视为正向票，得到正向比例下界 `p_lower`
- `confidenceScore = p_lower * 5`

3. 低样本惩罚与人工评分融合：

- 低样本惩罚：人数不足阈值时减小最终分的波动
- 当用户评分人数较低时，按权重融合人工评分（`game.star`）

4. 最终分：

`finalScore = 0.7 * bayesian + 0.3 * confidenceScore - penalty`  
再与人工评分按低样本权重融合并裁剪到 `1.0~5.0`。

## 5. 评论体系设计

- 根评论 + 回复列表
- 回复列表支持“默认折叠 + 展开更多 + 分页加载更多”
- 发布评论支持：
  - 普通评论：无 `parent_id`
  - 回复评论：带 `parent_id`
- 点赞支持乐观更新与失败回滚

## 6. 提醒开关设计

### 用户侧

- 字段：`reply_email_enabled`
- 开关入口：`/profile` 新增“通知设置”
- 提交评论时携带 `email_notify`（布尔）

### 管理侧

- 字段：`game_review_email_enabled`
- 入口：`/profile` 管理员可见配置卡片
- 关闭总开关后，用户侧邮件提醒能力自动失效

## 7. 兼容与降级

- 接口异常时前台页面保持可读，可继续展示人工评分与本地状态
- 评论与评分操作失败提供明确提示，不阻塞页面主流程
- 结构化数据无法拿到评分摘要时，回退到人工评分与下载量估算
